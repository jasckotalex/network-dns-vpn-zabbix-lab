# Безопасность: пошаговая настройка

В этом разделе настройки выполняются по порядку: от базовой связности до защищённого доступа к Zabbix.

## 1. Интерфейсы и маршруты

На ASA разделяются зоны доверия:

- `inside` — внутренняя сеть организации;
- `outside` — внешняя сеть и транзит через ISP-Router.

Внутренние маршруты направляют трафик к HQ и серверной сети через R-HQ. Внешний маршрут по умолчанию направляет трафик к ISP-Router.

Проверка маршрутов:

```text
show route
```

## 2. NAT для выхода во внешнюю сеть

Для внутренних сетей используется dynamic PAT. Внешний адрес ASA переиспользуется для исходящих соединений клиентов.

Проверка:

```text
show nat
```

## 3. Исключение NAT для VPN

Трафик между HQ и Branch не должен преобразовываться. Для этого создаются identity NAT-правила, сохраняющие исходные внутренние адреса.

Например, соединение между `10.10.20.0/24` и `10.20.10.0/24` должно проходить без изменения адресов.

## 4. ACL внешнего интерфейса

По умолчанию входящий трафик с `outside` блокируется. Для учебного доступа к Server-Zabbix разрешён только SSH:

```text
Источник: 192.168.96.0/24
Назначение: 10.10.20.20
Протокол: TCP
Порт: 22
```

Веб-порт Zabbix напрямую наружу не открывается.

Проверка ACL:

```text
show running-config access-group
show access-list OUTSIDE-IN
```

## 5. Site-to-site VPN

Между ASA-HQ и ASA-BRANCH настроен site-to-site VPN на базе IKEv2/IPsec.

Через VPN передаются внутренние сети:

```text
10.10.10.0/24 ↔ 10.20.10.0/24
10.10.20.0/24 ↔ 10.20.10.0/24
```

Проверка состояния:

```text
show crypto ikev2 sa
show crypto ipsec sa
```

Секретный PSK и другие чувствительные параметры в репозиторий не включаются.

## 6. Ограничение SNMP

На R-HQ SNMPv2c работает только в режиме чтения. Запросы разрешены только от Zabbix Server `10.10.20.20`.

Проверка с Zabbix Server:

```bash
snmpget -v2c -c <SNMP_COMMUNITY> 10.10.10.1 1.3.6.1.2.1.1.1.0
```

Вместо `<SNMP_COMMUNITY>` локально подставляется секретное значение.

## 7. SSH-туннель к Zabbix

Веб-интерфейс Zabbix доступен через SSH-туннель, поэтому порт веб-сервера не публикуется напрямую во внешнюю сеть.

```powershell
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 18080:127.0.0.1:8080 labadmin@10.10.20.20
```

После подключения интерфейс открывается по адресу:

```text
http://127.0.0.1:18080
```

Параметры команды:

- `-N` — не запускать удалённую оболочку;
- `-L` — создать локальное перенаправление порта;
- `18080` — локальный порт Windows;
- `127.0.0.1:8080` — веб-порт Nginx на Server-Zabbix;
- `ServerAliveInterval` и `ServerAliveCountMax` — поддерживать соединение и обнаруживать обрыв.

## 8. Итоговые проверки

```text
show route
show nat
show access-list OUTSIDE-IN
show crypto ikev2 sa
show crypto ipsec sa
```

С Linux-сервера:

```bash
nc -vz -w 3 10.10.20.10 10050
```

С Windows:

```powershell
Test-NetConnection 10.10.20.20 -Port 22
```
